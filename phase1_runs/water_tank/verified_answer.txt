Setup: R(t) = 300t - 30t^2 gallons/hour on 0 <= t <= 8. Since R(t) = 30t(10-t), R(t) >= 0 on the whole domain (R(t) = 0 only at t = 0 and t = 10, and 10 lies outside [0,8]), so the model describes a nonnegative inflow rate over the entire refill window; this is also a first self-check confirming the model is physically sensible before it is used.

(i) Peak inflow rate: differentiate, R'(t) = 300 - 60t. Setting R'(t) = 0 gives 60t = 300, so t = 5, which lies in the open interval (0,8), so it is an interior critical point. R''(t) = -60 < 0 for all t, so t = 5 is a local maximum; since R is continuous on the closed, bounded interval [0,8], the closed-interval method applies: compare the critical point's value against both endpoints. R(0) = 300(0) - 30(0)^2 = 0. R(8) = 300(8) - 30(8)^2 = 2400 - 1920 = 480. R(5) = 300(5) - 30(5)^2 = 1500 - 750 = 750. Comparing 0, 750, and 480, the greatest value is 750, occurring at t = 5, so the inflow rate is greatest at t = 5 hours, when R(5) = 750 gallons per hour. Self-check: R'(5) = 300 - 60(5) = 300 - 300 = 0 confirms t = 5 is a critical point, and 750 exceeds both endpoint values, confirming it is the absolute maximum on [0,8], not merely a local one.

(ii) Total volume from t = 0 to t = 8: by the net change theorem, the total volume V equals the integral of the rate function, V = integral of R(t) dt from 0 to 8. An antiderivative of R(t) = 300t - 30t^2 is F(t) = 150t^2 - 10t^3 (since d/dt[150t^2] = 300t and d/dt[-10t^3] = -30t^2). By the evaluation theorem, V = F(8) - F(0) = [150(8)^2 - 10(8)^3] - [150(0)^2 - 10(0)^3] = [150(64) - 10(512)] - 0 = [9600 - 5120] - 0 = 4480. So the total volume added over the 8-hour window is 4480 gallons. Self-check by splitting the interval at the critical point t = 5: integral from 0 to 5 = [150(25) - 10(125)] - 0 = 3750 - 1250 = 2500; integral from 5 to 8 = [150(64) - 10(512)] - [150(25) - 10(125)] = (9600 - 5120) - (3750 - 1250) = 4480 - 2500 = 1980; and 2500 + 1980 = 4480, matching the direct computation and confirming the arithmetic.

(iii) Overflow comparison: the protocol engages only if more than 5,000 gallons enter during the window. Since the actual total is 4480 gallons and 4480 < 5000, the total falls short of the threshold, so the overflow protocol does NOT engage during this 8-hour refill window.

(iv) Technician's estimate versus the true total: the technician computes peak rate times duration, 750 gallons/hour times 8 hours = 6000 gallons. This 6000-gallon estimate is larger than the true total of 4480 gallons, overstating it by 1520 gallons. The discrepancy exists because R(t) is not a constant function of t: R(t) is a downward-opening parabola in t over [0,8] with a single peak at t = 5, so R(t) is strictly below its peak value of 750 at every other time in the window (R(0) = 0 and R(8) = 480, and by continuity R(t) < 750 everywhere in [0,8] except the single instant t = 5). Multiplying the peak rate by the full 8 hours implicitly assumes the tank fills at 750 gallons per hour continuously for the entire window, but the true rate is below 750 for all but a single instant, so that estimate overcounts. The correct total requires integrating the actual, time-varying rate over the interval (the net change theorem used in part (ii)); equivalently, the correct total equals the interval's average rate, not its peak rate, times the duration: the average rate here is 4480 gallons / 8 hours = 560 gallons per hour, which is indeed below the peak of 750, exactly as the discrepancy requires. This gap also matters for the decision in part (iii): the technician's 6000-gallon estimate would have wrongly implied the overflow protocol engages (6000 > 5000), while the true 4480-gallon total shows it does not; using the peak-rate shortcut instead of the actual integral would have flipped the protocol decision.
